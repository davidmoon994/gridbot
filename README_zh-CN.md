# GridBot · 移动网格自动交易机器人

参考 [NOFX](https://github.com/NoFxAiOS/nofx) 的"策略提议 + 代码层风控强制执行"架构，
用经典的**移动网格算法**（EMA 跟随中心 + ATR 自适应间距 + 自动重新居中）替代 AI 决策层，
带 Web 控制台，Go 编写，单文件部署。

详细架构设计见 [docs/ARCHITECTURE_zh-CN.md](docs/ARCHITECTURE_zh-CN.md)。

## 特性

- **移动网格**：网格中心跟随 EMA 移动，间距按 ATR 动态调整，价格突破网格范围时自动重新居中，避免被套在单边趋势里
- **风控硬约束**：杠杆上限、单币种仓位占比、总保证金使用率、当日亏损熔断、极端行情熔断——全部在代码层强制执行，网格参数无法绕开
- **交易所可插拔**：内置 Binance USDⓈ-M合约/现货、OKX V5永续合约/现货、模拟盘（Paper Trading）五种实现，只需实现 `exchange.Exchange` 接口即可接入更多交易所
- **API Key 运行时绑定**：币安/OKX 的 API Key 不写在代码或配置文件里，登录 Web 控制台后在"交易所账号"面板绑定/解绑/切换，保存在本地数据库，重启自动恢复
- **账号登录**：Web 控制台需要账号密码才能访问，首次使用会引导创建管理账户
- **Web 控制台**：内嵌单文件前端，网格结构可视化、事件日志、启停控制，单个二进制文件即可部署
- **SQLite 持久化**：网格配置、成交事件、盈亏历史、交易所凭证、管理账户，重启自动恢复

## 快速开始

### 环境要求

- Go 1.22+
- GCC（SQLite 驱动 `mattn/go-sqlite3` 需要 CGO）

### 运行（模拟盘，无需任何 API Key）

```bash
go mod tidy
go build -o gridbot .
./gridbot -config config.json
```

首次运行会在当前目录生成默认的 `config.json`（模拟盘模式，10000 USDT 初始资金，
预置 BTCUSDT/ETHUSDT/SOLUSDT 三个交易对的初始价格）。

打开浏览器访问 `http://127.0.0.1:3000`：

1. **首次访问**会自动跳转到初始化页面，创建一个管理账户（用户名+密码，只能创建一次）
2. 之后每次访问都需要登录，未登录无法访问控制台的任何页面和接口
3. 登录后在左侧"交易所账号"面板绑定币安/OKX 的 API Key（见下方"接入真实交易所"），
   不绑定的话默认使用内置模拟盘

### 启动一个网格策略

在左侧"新建网格策略"表单中：

1. 填写交易对（模拟盘需与 `config.json` 里 `paper_initial_prices` 中的键一致，如 `BTCUSDT`）
2. 选择模式：
   - `long_only`（只做多）：低位买入开多/加仓，高位卖出止盈，不做空，风险较低
   - `neutral`（中性双向）：低位开多、高位开空，两个方向都能吃震荡利润，收益更高但需要交易所支持双向持仓，风险也更高
3. 设置杠杆、网格层数、每格金额等参数
4. 点击"启动网格"

也可以直接调用 API：

```bash
curl -X POST http://127.0.0.1:3000/api/grids \
  -H "Content-Type: application/json" \
  -d '{
    "symbol": "BTCUSDT",
    "mode": "neutral",
    "leverage": 3,
    "grid_count": 8,
    "per_grid_quote_amount": 50,
    "atr_spacing_multiplier": 0.6,
    "recenter_threshold_grids": 6,
    "max_total_position_quote": 2000
  }'
```

## 现货 vs 合约

绑定交易所时可以选"合约"或"现货"，两者的关键区别：

- **现货没有杠杆、不能做空**：绑定现货交易所后，"新建网格策略"表单会自动把模式
  锁定为「只做多」、杠杆锁定为1，"中性双向"模式在现货下无法使用（服务端会拒绝，
  不只是界面隐藏）
- **现货没有交易所原生"持仓"查询**：程序会用网格引擎自己的成交记账（买了多少、
  什么价位）来做仓位占比风控和回撤保护判断，不依赖交易所的持仓接口
- 币安现货计价货币同样建议用 `USDC`（同样享受手续费优惠）；OKX 现货和合约共用
  同一套代码，只是内部标记不同市场类型

## 接入真实交易所

币安（USDⓈ-M合约）和 OKX（V5永续合约）都已经是完整实现，不需要写代码，直接在
Web 控制台的"交易所账号"面板绑定即可：

1. 登录控制台，左侧"交易所账号"选择币安或OKX，填入 API Key / Secret
   （OKX 还需要 Passphrase），计价货币填 `USDC`（或 `USDT`），点击"绑定并启用"
2. 绑定后会立即做一次连接测试（拉取余额），成功才会切换为当前生效交易所；
   如果失败，凭证仍会保存，检查 Key/权限/网络后可以直接点"启用"重试，不用重新输入
3. **强烈建议先勾选"测试网/模拟盘"验证下单/撤单/查询全流程无误后再切到实盘**
4. 如果要用 `neutral`（双向持仓）网格模式，记得同时打开"双向持仓"选项，
   并在交易所官网账户设置里把"持仓模式"也改成对应的双向/长空模式，两边要一致
5. 交易对直接填 `BTCUSDC`/`ETHUSDC` 这类符号即可，无论是币安还是OKX都会自动转换成
   各自要求的格式（OKX 会转成 `BTC-USDC-SWAP`）

想接入 Bybit 等其他交易所：实现 `exchange.Exchange` 接口，在 `exfactory/factory.go`
里注册一下类型标识即可，网格引擎（`strategy`）、风控引擎（`risk`）、Web 层（`server`）
都不需要任何改动。

## 项目结构

```
gridbot/
├── main.go                    # 程序入口
├── config/                    # 配置加载
├── exchange/                  # 交易所接口 + Paper实现 + Binance骨架
├── strategy/                  # 移动网格引擎 + EMA/ATR指标
├── risk/                      # 风控引擎 + 风控装饰器
├── manager/                   # 调度层：串联策略/风控/交易所/存储
├── store/                     # SQLite 持久化
├── server/                    # HTTP API + 内嵌 Web 控制台
│   └── webroot/index.html
└── docs/
    └── ARCHITECTURE_zh-CN.md  # 详细架构设计文档
```

## 风险提示

- 本项目为参考实现，**默认使用模拟盘运行**，接入真实资金前请充分测试
- `neutral`（双向）模式和高杠杆意味着更高风险，请先用小额资金和低杠杆验证
- 强平保护目前只记录事件、不会自动下单平仓（详见架构文档），如需自动执行需要你自行接入并充分测试
- 加密货币衍生品交易存在爆仓风险，本项目不构成任何投资建议
